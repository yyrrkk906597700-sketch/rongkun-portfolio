# Rongkun 摄影师个人作品集研究

研究日期：2026-10-01  
研究对象：当前 React + Vite 个人摄影师作品集网站  
目标客户：品牌客户、广告公司、需要商业拍摄的客户

## 研究决策

这次研究需要回答四个问题：

1. 首页应该先让客户理解什么？
2. 作品应该如何展示，才能证明商业拍摄能力？
3. 个人经历如何从“履历”变成客户可感知的能力证明？
4. 客户看完页面后，如何低成本地发起合作咨询？

## Handoff Context

- App：Rongkun 摄影师个人作品集
- 平台：响应式 Web，React + Vite
- 当前约束：PC 与手机端都要可用，版心约 1700px，保留照片、流光背景和现有动效
- 已知证据：宣传片、纪录片、TVC、课程、短视频拍摄；具备摄影、灯光、场景、后期剪辑调色、编导和小红书运营经验；曾做出单条 400 万播放内容
- 主要未决问题：真实客户名称和可公开案例、作品授权范围、常用拍摄城市、预算区间、微信或邮箱联系方式、希望优先承接的项目类型

## 研究方法与限制

本报告使用三类证据：

1. 审计当前源码中的页面结构、文案、链接和资源。
2. 观察公开摄影师/制作机构网站的导航、项目入口和联系路径。
3. 对照 W3C、web.dev 和 Nielsen Norman Group 的公开 UX 指南。

外部网站只用于提炼结构模式，不代表它们的业务数据可以直接复制。当前没有真实客户转化数据，因此 CTA 和页面顺序是基于目标客户与行业模式的可验证假设，后续应通过咨询点击、表单提交和来源统计验证。

## 关键结论

### 1. 首页的视觉吸引力已有基础，但客户价值表达不够快

当前首屏有姓名、个人照片、中文简介、年龄/民族/籍贯和 Contact Me 按钮（`src/main.tsx:65-79`）。照片和动效能建立记忆点，但品牌客户通常在几秒内先判断三件事：拍什么、服务谁、能否稳定交付。年龄、民族和籍贯应降为辅助信息，不能占据与商业能力同等的注意力。

建议首屏主句直接变成：

> 商业影像摄影师 / 编导，专注宣传片、TVC、品牌内容与短视频。

副句保留一行可信证明：从前期策划、现场摄影、灯光协作到后期剪辑调色，能够独立推进完整制作流程。主 CTA 使用“查看案例”，次 CTA 使用“预约拍摄 / 获取报价”。

### 2. 当前作品展示会削弱可信度

当前 `projects` 数据仍使用 `Nextlevel Studio`、`Aura Brand Identity`、`Solaris Digital` 等 3D/品牌示例名称和远程示例图（`src/main.tsx:18-43`）。对商业客户来说，这会让页面看起来像通用模板，无法证明河源、佛山和短视频项目经验。

建议用 6—8 个真实且获授权的精选案例替换无限滚动图片。每个案例至少显示：

- 项目名称与年份
- 客户/行业（无法公开时写“某消费品牌”）
- 项目类型：宣传片、纪录片、TVC、短视频等
- 你的职责：摄影、灯光、编导、后期
- 可公开的结果：播放量、传播范围、交付数量或项目周期

首页先展示 3 个最有说服力的案例，其他案例放入“全部作品”。点击案例后进入详情页或展开面板，按“目标—执行—结果”讲清楚，而不是只放图片。

### 3. Services 的内容与摄影定位不一致

当前服务列表仍是 `3D Modeling`、`Rendering`、`Motion Design`、`Branding`、`Web Design`（`src/main.tsx:97-98`），导航却把它标为 `Price`。这会让广告公司误以为网站属于 3D 设计师，也没有回答“你能否完成商业拍摄”。

建议改为：

- 宣传片 / 品牌片拍摄
- TVC 与广告片摄影
- 纪录片与人物采访
- 短视频策划、拍摄与剪辑
- 灯光、场景与现场执行

“Price”应改成“Services”或“服务范围”。除非已经有标准套餐，否则不要在首页把服务导航命名为 Price。

### 4. 工作经历应该作为能力证明，而不是单独的简历墙

当前经历区已经按 2022—2026 年分为三段，并包含公司、职位、职责和成果（`src/main.tsx:100-125`）。这个方向正确，但每段应优先突出“客户因此得到什么”：能独立完成哪些环节、处理多大规模的现场、如何控制质量和交付。

建议保留三段时间线，同时把成果写成可扫描的短句：

- 负责从前期策划到成片交付的完整流程
- 参与多类型剧组，具备现场协作和快速判断能力
- 从零起号增长至 4,000+ 粉丝，打造单条 400 万播放内容

如果客户名称不能公开，用行业标签替代公司名，并保留项目类型和个人职责。经历区之后应紧跟“合作方式 / 常见交付内容”，把履历转成下一步行动。

### 5. 转化路径需要从“看完”变成“马上联系”

当前 Contact Me 只跳转到页脚，页脚使用 `hello@jack3d.studio`（`src/main.tsx:130`）。这条路径缺少客户发起咨询所需的信息，也没有项目预期、联系方式和回复时间。

建议设计成三步：

1. **首屏**：查看案例（主 CTA）+ 预约拍摄（次 CTA）。
2. **案例/经历之后**：加入“告诉我你的项目”按钮，链接到短表单或微信二维码。
3. **页脚**：显示真实邮箱、微信、常驻城市、可承接城市、通常回复时间，并允许直接复制联系方式。

联系表单只保留必要字段：姓名/公司、项目类型、拍摄城市、预计时间、联系方式、项目简介。手机端可以增加固定底部 CTA，但不能遮挡内容或依赖 hover。

## 推荐首页信息层级

1. **Hero**：一句定位 + 代表性照片 + 2 个 CTA。
2. **精选作品**：先展示 3 个真实案例，每个有类型、职责和结果。
3. **能力范围**：摄影、编导、灯光、后期，用客户语言描述交付物。
4. **可信证明**：项目数量、播放量、合作行业或客户 Logo（获得授权后）。
5. **工作经历**：时间线，突出职责和可验证成果。
6. **合作流程**：需求沟通 → 前期方案 → 现场拍摄 → 后期交付。
7. **联系区**：表单、微信、邮箱和回复预期。

当前页面顺序是 Hero → 图片 Marquee → About → Services → Experience → Projects → Footer。建议把真实精选作品提前到 About 之前，把 Marquee 降为作品预览或删除；客户应先看到与你摄影方向直接相关的案例，再阅读经历。

## 作品详情页建议模板

```text
项目名称 / 年份
客户行业 / 项目类型
我的职责：摄影 / 编导 / 灯光 / 后期

项目目标：客户希望解决什么问题
执行过程：前期准备、现场规模、画面与灯光策略
交付结果：成片数量、播放量、传播或上线渠道
```

图片和视频应保留真实比例，并为每个媒体预留尺寸，避免加载时页面跳动。当前个人照片 `public/assets/rongkun.jpg` 约 11.76 MB，正式上线前应导出 WebP/AVIF 并提供合适尺寸，降低首屏等待。

## 优先级路线图

### P0：先修正定位和信任

- 用摄影真实案例替换 3D 示例项目。
- 把 Services 改成摄影/编导/后期相关服务。
- 把 `Price` 改为 `Services` 或 `服务范围`。
- 将 `hello@jack3d.studio` 换成真实邮箱与微信入口。
- 首屏 CTA 改成“查看案例”和“预约拍摄”。

### P1：提高案例理解和转化

- 为 3 个精选案例增加详情内容。
- 在经历区突出 4,000+ 粉丝和 400 万播放等可验证成果。
- 增加合作流程和项目需求表单。
- 移动端增加清晰的固定联系入口，保证触控区域至少 44×44px。

### P2：性能和持续优化

- 压缩照片、GIF 和远程图片，优先使用 WebP/AVIF。
- 给媒体固定宽高或 `aspect-ratio`，减少布局跳动。
- 记录 CTA 点击、案例打开、表单开始和提交成功事件。
- 用真实访问数据决定保留哪些动效和 Marquee。

## 验证指标

- 首屏“查看案例”点击率
- 精选案例打开率和详情页完成阅读率
- 联系按钮点击率
- 表单开始率与提交率
- 不同设备的首屏加载和布局稳定性
- 咨询来源：品牌方、广告公司、个人客户

没有数据前，不建议用“感觉更高级”判断改版是否成功。先建立事件记录，再根据 2—4 周数据调整案例顺序和 CTA 文案。

## 外部证据与观察

访问日期：2026-10-01。

- [Martin Parr](https://www.martinparr.com/)：导航明确拆分 `Introduction`、`Recent Work`、`CV`、`Contact` 等入口，说明个人背景、作品和联系路径应分层组织，而不是混在一个视觉区块里。
- [Magnum Photographers](https://www.magnumphotos.com/photographers/)：以 `Stories`、`Photographers`、`Learn` 等内容入口组织专业内容，作品展示不仅是图片墙，也包含人物、故事和专业能力入口。
- [Magnet Media](https://www.magnetmediafilms.com/)：首页将 `Services`、`Work`、`About`、`get started` 并列，并在案例中同时展示客户、内容类型和项目目标，适合参考商业内容机构的转化结构。
- [W3C WCAG 1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)：普通文字建议至少达到 4.5:1 对比度，大号文字至少 3:1。网站的浅色文字和流光背景需要按实际组合检查，而不能只看单独颜色。
- [web.dev CLS](https://web.dev/articles/cls)：布局突然移动会导致用户阅读位置改变或误点按钮；图片、字体和第三方内容应预留尺寸，目标是把 CLS 控制在良好范围。
- [Nielsen Norman Group 可用性启发式](https://www.nngroup.com/articles/ten-usability-heuristics/)：强调系统状态可见性、一致性和“识别而非回忆”。因此导航名称、CTA 文案和案例标签应使用客户熟悉的词，不要让用户猜 `Price` 是否代表服务。

## 待确认问题

1. 哪些案例可以公开展示？是否需要隐去客户名称或打码？
2. 你最想优先承接宣传片、TVC、纪录片还是短视频项目？
3. 常驻城市和可接受的出差范围是什么？
4. 真实邮箱、微信或电话是什么？预计多久回复客户？
5. 是否有客户 Logo、上线链接、播放量截图或成片链接可以作为证明？
6. 你希望网站主要获得中文客户，还是需要同时服务英文客户？

这些答案会直接决定案例顺序、语言、CTA 和联系表单字段。
